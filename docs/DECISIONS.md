# Decisions
- **Simulator: MuJoCo 3.14.0** (default per PLAN). Open question "existing ROS 2 stack?" unanswered -> no Gazebo. Revisit only if a ROS 2 stack exists.
- **Motion checking is kinematic**: straight-line segments sampled at 1 mm, MuJoCo contact queries + joint-limit tests. No dynamics, no liquids.
- **Failure policy**: first failure stops the run and is reported; nothing is clipped.
- **Environment**: Python 3.12 venv, `requirements.lock` pinned. mp4 replay uses MuJoCo renderer (GLFW on macOS) + imageio-ffmpeg.
- **Scene/spec coupling**: spec coordinates (mm) are authored to match `scene.xml`; the scene hash is recorded per run.
- **LLM provider (2026-10-03, project owner): a development model for now; OpenAI at deployment.** PLAN names OpenAI and the challenge brief says track prizes need OpenAI models. All services use the provider-agnostic `atlas.llm.LLMClient`; an `OpenAIClient` adapter is added before deployment. Before the first live call: pin model + prompt + schema here, get human approval to send data (no PHI/PII; permitted passages only). Superseded: OpenAI only (see the last entry).
- **Volume-ledger tolerance (2026-10-03): `LEDGER_TOL_UL = 1e-9` uL** in `robotics/compile_workflow.py` so valid splits like 0.1 + 0.2 from a 0.3 uL aspirate are not rejected by float round-off (QA finding F1). Real overdraws still fail. Verdicts of the five fixtures are unchanged.
- **Uploads cannot overwrite claims (2026-10-03):** `ingest_lab_finding` quarantines a payload whose `claim_id` already exists (QA finding F2).
- **`fastapi` and `networkx` stay declared though not yet imported:** docs/implementation/02 and 05 plan the API and graph code that will use them.

  - Storage is stdlib `sqlite3` (STRICT tables: indexed columns + validated JSON body) plus a deterministic JSONL snapshot with per-file SHA-256 (`src/atlas/db.py`). No ORM. Postgres is the later path behind the same interface.

  - `Claim` gains optional PLAN provenance fields (`published_at`, `retrieved_at`, `extraction_method`, `source_reported_classification`, `review_notes`, `derived_from`) and the Biolink `knowledge_level` / `agent_type` enums (default `not_provided`). The KGX export is deferred.

## 2026-10-04 - Independent studies versus background restatements (owner direction); log and drug-claim switch
- Owner direction: a paper that only cites a statement as "background knowledge" adds some weight but less than an independent study; and one study that proves something well is enough (no replication is demanded). Verified means: a MeSH heading in a medical branch of the tree (A anatomy, B organisms, C diseases and symptoms, D chemicals and drugs, E procedures, F mental health, G biological processes except G17 mathematical concepts), or a condition name (it contains a condition word) that appears in the titles of at least 2 PubMed-indexed journal articles that are not retractions or editorials. ## 2026-10-04 (later): development provider, related diseases, clusters by search

- **A development provider was used until the owner said otherwise.** Superseded the same day: OpenAI only (next entry).
- **Related diseases use the raw reference data** (`atlas/related.py`, `GET /api/entities/{id}/related-diseases`). One row per disease, with every reason and its origin: shared gene (HPO genes_to_disease), same MONDO family, a mechanism observed in papers, a paper link (often a hypothesis), an AI hypothesis, and symptom similarity of at least 0.4 (computed over every annotated disease, not a 12-item candidate list). When nothing links a disease, the page says "No similarities found".
- **Clusters are defined relative to a search.** A cluster is the group of diseases that share one specific thing with the searched disease (one gene, one mechanism, one parent disease, a similar symptom pattern, or a proposed link). The page opens only with a searched disease, explains what a cluster is and is not, and is built from the related-diseases data. The store-wide `/clusters` and `/entities/{id}/clusters` endpoints were removed.
- **Navigation.** Top bar: Home, Symptoms, Simulation. After a search, a second row offers Dossier, Graph and Clusters (no Dossier link on the Graph page). The "seed cluster" label was removed: those were four example entries picked on 2026-10-03, not a cluster.
- **Simulation is a closed-loop experiment, as a robot would run it** (owner direction 2026-10-04; `atlas/experiment.py`, `/api/experiments/*`, `frontend/src/routes/simulation.tsx`; research basis in `docs/research/closed_loop_experiments.md`). The researcher defines the experiment: parameters with units, ranges and the largest change allowed per run; fixed parameters; instrument limits; plate layout (outer wells as buffer by default, because of the edge effect); pass criteria; "if this fails, change that" rules; how many passing runs in a row are needed; and the most runs overnight. The robot plan is checked with real arithmetic (pipette range, stock strength, DMSO limit, well volume, tips) and the MuJoCo motion check, and is refused rather than adjusted when a limit is broken. Runs are scored by formula (Z', CVs, signal/background, 4PL fit, points on each plateau using Sebaugh's bend points). The next run changes only what a rule allows, within range; a refused change is shown with the reason. An AI review, when a key is configured and asked for, may only pick among the allowed changes, and its choice is re-checked. Confirmation needs consecutive passing runs with the same settings. Readings are MEASURED (from the researcher's plate reader) or SYNTHETIC (a stated 4PL model with noise and an edge effect, for showing the loop); the label travels with every run and synthetic values are never evidence. Defaults follow the NIH Assay Guidance Manual (Z' threshold set by the researcher, 0.5 by default; control CV of at most 20%) and Sebaugh 2011 (2 points beyond each bend); the default rules are a design, not a published standard. The scene has one reservoir position, so the motion check draws every aspiration there. The old recorded-run replay page was replaced; its `/simulations/{id}` endpoint remains for the stored demo runs.
